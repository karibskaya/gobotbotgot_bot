# Brief Bot

Бот для брифования клиентов

Бот помогает автоматизировать первичную коммуникацию с клиентом: пользователь выбирает тип брифа, проходит последовательность вопросов, оставляет контактные данные, а администратор получает структурированную анкету в Telegram.

Проект показывает, как хаотичную переписку с клиентом можно перевести в понятный сценарий с ролями, состояниями, вопросами и результатом на выходе.

## Задача проекта

В небольших цифровых проектах первичный бриф часто собирается вручную: в переписке, голосовых сообщениях, заметках или таблицах. Из-за этого ответы приходят в разном формате, важные детали теряются, а администратор тратит время на уточнения.

Цель бота — стандартизировать сбор информации перед началом работы над проектом и снизить ручную нагрузку на администратора.

## Что умеет бот

- показывает пользователю меню с вариантами брифа;
- запускает отдельный сценарий вопросов для выбранного типа заявки;
- последовательно собирает ответы пользователя;
- скрывает обычную клавиатуру после выбора сценария;
- запрашивает контакт для связи после завершения вопросов;
- формирует итоговую анкету в структурированном виде;
- отправляет анкету администратору в Telegram;
- предлагает заполнить ещё один бриф через inline-кнопку.

## Типы брифов

В текущей версии реализованы три сценария:

### Консультация

Короткий сценарий для первичного запроса. Помогает понять идею проекта, задачи клиента, текущую ситуацию и формат дальнейшей работы.

### Бот для ленивых

Сценарий для простого бота с понятной задачей: выдача материалов, сбор заявок, фильтрация клиентов, FAQ, ссылка на оплату и другие базовые функции.

### Бот под ключ

Подробный бриф для сложной разработки. Собирает информацию о бизнесе, целевой аудитории, задачах бота, API, базе данных, нагрузке, бюджете, сроках, сценариях, контенте и будущей поддержке.

## Пользовательский сценарий

1. Пользователь запускает бота командой `/start`.
2. Бот предлагает выбрать тип брифа.
3. Пользователь выбирает сценарий.
4. Бот последовательно задаёт вопросы из выбранного брифа.
5. Пользователь отвечает на каждый вопрос.
6. После последнего вопроса бот просит оставить контакт для связи.
7. Бот отправляет пользователю сообщение с благодарностью.
8. Бот отправляет администратору структурированную анкету.
9. Пользователь может нажать кнопку «Ещё один бриф» и пройти другой сценарий.

## Роли

### Пользователь

Выбирает тип брифа, отвечает на вопросы и оставляет контактные данные.

### Администратор

Получает готовую анкету в Telegram и может использовать её для оценки задачи, подготовки предложения или дальнейшей коммуникации с клиентом.

## Логика состояний

Бот построен на `ConversationHandler` из библиотеки `python-telegram-bot`.

Используются три состояния:

- `CHOOSING_BOT` — пользователь выбирает тип брифа;
- `ASKING_QUESTIONS` — бот задаёт вопросы и собирает ответы;
- `ASKING_CONTACT` — бот запрашивает контакт для связи.

Ответы временно хранятся в словаре `user_data`, где ключом выступает `chat_id` пользователя.

## Структура данных

Сценарии брифов хранятся в словаре `briefs`.

Каждый ключ словаря — название брифа, а значение — список вопросов:

```python
briefs = {
    "Консультация": [...],
    "Бот для ленивых": [...],
    "Бот под ключ": [...]
}
```

Такую структуру легко расширять: чтобы добавить новый бриф, достаточно добавить новый ключ и список вопросов.

Контакт для связи:

## Как запустить проект

Клонировать репозиторий:
git clone https://github.com/karibskaya/gobotbotgot_bot.git
cd gobotbotgot_bot

Установить зависимости:
pip install python-telegram-bot

Создать переменную окружения с токеном бота:
export BOT_TOKEN="your_telegram_bot_token"

Запустить бота:
python main.py

## Настройки

В коде используются две основные настройки:

TOKEN = os.getenv("BOT_TOKEN")
ADMIN_ID = "TELEGRAM_USER_ID"

TOKEN — токен Telegram-бота.
ADMIN_ID — Telegram ID администратора, которому бот отправляет заполненные анкеты.

## Что можно улучшить

добавить валидацию контактов;
добавить команду /cancel;

добавить несколько администраторов;
добавить админ-панель для редактирования сценариев без изменения кода;
добавить логирование ошибок и действий пользователей;
добавить деплой на сервер или PaaS-платформу.


## Статус проекта

Учебно-практический проект.
Бот показывает базовую архитектуру сценарного Telegram-бота: выбор сценария, прохождение вопросов, сбор данных, отправка результата администратору и повторный запуск брифа.
